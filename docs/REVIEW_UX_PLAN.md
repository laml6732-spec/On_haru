# Review UX 개편 — 문제와 판단 기준
상태: 기획 제안 / 구현 전 검토 · 2026-11-06 (하와이)
기준: main 8060aea9 / 실제 앱 소스 ac999bc5, DESIGN.md, 기존 캡처 42장과 라이브 검토.
범위: Review의 정보 구조와 기존 기록 표현. 앱 코드·스키마·데이터·백업·복구·PWA 변경 없음.

## 1. 목표와 근거
Review의 첫 화면만 보고 ‘어느 날인지, 어떤 기분이었는지, 무엇을 기록했는지’를 파악할 수 있게 한다.
기능 추가보다 선택지 수, 반복 라벨, 시각적 경쟁을 줄인다. 카드 개수를 줄이는 것만으로 완료하지 않는다.
사용 빈도 로그나 사용자 테스트는 없다. 아래 행동 순서는 회고 앱 목적과 사용자의 불편을 바탕으로 한 가정이며 검증 대상이다.

## 2. 사용 행동과 우선순위
| 순서 | 행동 | 화면에서 우선할 것 |
| --- | --- | --- |
| 1 | 선택한 날의 경험/생각 다시 읽기 | 날짜와 실제 기록 본문 |
| 2 | 그날의 감정/에너지 확인 | 표정·기분 값·에너지 값, 기록 시점 |
| 3 | 며칠의 흐름을 비교하고 회고 | 7일 기분과 에너지, 기존 주간 회고 |
| 4 | 특정 과거 기록 찾기 | 검색, 날짜, 필요한 분류 |
| 5 | 수정/다시 볼 기록 표시 | 기록 가까운 보조 액션, 기존 저장 의미 유지 |

날짜와 Mood는 기록을 이해하는 짧은 머리말이다. 상단을 크게 장식해 첫 기록을 밀어내지 않는다.

## 3. 현재 문제
| 문제 | 확인 근거 | UX 영향 |
| --- | --- | --- |
| 탐색 기준이 중첩됨 | Daily/Weekly/Archive 아래 Records/Mood | 원하는 내용을 찾기 전에 UI 분류를 해석해야 함 |
| 라벨이 본문보다 많음 | 날짜→3분류→일정→제목→태그→시간 | 읽기 전에 문맥을 반복해서 해독함 |
| Mood 진입이 깊음 | Archive에서 다시 Mood 선택 | 감정이 회고의 일부로 잘 드러나지 않음 |
| 감정 표시가 추상적임 | 작은 색·도형과 범례에 의미 의존 | 실제 감정 수준을 직관적으로 읽기 어려움 |
| 여러 선택 상태가 경쟁함 | 탭, 분할선택, 전체/다시볼기록, 필터칩 | 현재 탐색 맥락을 한 번에 파악하기 어려움 |
| 본문이 촘촘함 | 라이브 Daily 13.5px / 줄높이 약 1.225 | 긴 한영 문장을 읽기 피곤함 |
| 제목/본문 위계 약함 | Archive에서 같은 작은 글줄로 이어짐 | 핵심 생각을 훑기 어려움 |
| 일부 의미가 불분명함 | 별, 중요, 다시 볼 기록, 태그의 공존 | 서로 다른 기능인지 판단하기 어려움 |

탭 수 자체가 잘못은 아니다. 기간, 콘텐츠 종류, 행동 목적을 같은 수준에 섞어 놓은 것이 문제라는 판단이다.
최근 그래프 개선과 ☆/★ 버튼은 이미 존재한다. ‘그래프 없음/표시할 버튼 없음’을 현재 문제로 재기재하지 않는다.

## 4. 구조 선택
| 안 | 구성 | 장단점 |
| --- | --- | --- |
| A | Daily/Weekly/Archive 유지, 상단 Mood와 라벨만 정리 | 구현 위험 낮지만 중첩 탐색과 모드 간 중복이 남음 |
| B · 우선안 | 돌아보기 / 찾기, 돌아보기 안에서 하루/주간 기간 전환 | 목적이 분명하고 Mood와 기록을 함께 읽기 쉬움. 기존 경로를 옮기는 회귀 확인 필요 |

B안을 기획 우선안으로 선택한다. 아직 사용자가 화면 배치까지 확정한 것은 아니다.
‘하루/주간’은 기간 제어이며 ‘돌아보기/찾기’는 목적 선택이다. 같은 모양의 탭 두 줄을 쌓지 않는다.
상단에는 한 종류의 목적 탐색만 두고, 기간 제어는 날짜 옆에 작고 명확하게 둔다.
하단 앱 5탭은 유지한다. Review 안의 기존 기능은 새 목적에 재배치한다.

## 5. 구체적인 배치 원칙
### 돌아보기 · 하루
- 날짜(오른쪽 기분 표정·색) → 기록 목록 → 기존 하루 회고 순서.
- 날짜 오른쪽에 기분 표정 하나와 기존 Mood×Energy 색만 표시한다. 별도 Mood 요약칸, 점수·시점·시간·에너지 막대는 기본 화면에서 제거한다.
- 하루 마무리 기록이 있으면 우선 표시. 없으면 같은 날 최신으로 기록된 유효 시점과 라벨을 표시한다.
- 시각이 없거나 순서를 확정할 수 없으면 고정 시점 우선순위를 문서화한다. 의미를 추측해 점수를 생성하지 않는다.
- 다른 시점의 원본 Mood도 기존 기록 상세에서 접근 가능하게 한다. 요약이 과거 데이터를 숨겨 없애서는 안 된다.
- 기록은 시간순 읽기를 기본으로 검토한다. 시간대/3분류 제목을 동시에 전부 표시하지 않는다.
- 한 기록은 시간·기록 종류·필요한 일정명 한 줄 → 제목이 있으면 굵게 → 본문으로만 구성한다. 제목이 없으면 본문만 표시한다.
- 같은 일정에 여러 메모가 있으면 일정명을 한 번만 표시한다. 제목과 일정명이 같으면 메타의 일정명을 생략하고 사용자 제목은 굵게 남긴다. 제목/원문을 수정하지 않는다.
- ‘오늘의 감사’ 아래 ‘감사’, ‘가족을 위한 기도’ 아래 태그 ‘기도’, ‘기도 10분’ 뒤 종류 ‘기도’를 반복하지 않는다. 사용자 원문 속 단어는 중복 제거 대상으로 삼지 않는다.
- 기록 본문을 눌러 읽고, 기존 수정은 보조 동작으로 구분한다. 스크롤 중 우발적 편집을 줄인다.

### 돌아보기 · 주간
- 기간 → 7일 감정 흐름 → 그 주 기록 → 기존 주간 회고 순서.
- 7일 그래프는 기존 하루 마무리 Mood/Energy만 사용한다. 기본 주간 읽기에서는 날짜별 표정·색만 표시하고 그래프는 ‘기분·에너지 흐름’ 펼침에서 확인한다. 하루 화면의 최신 시점 대체 규칙을 그래프에 적용하지 않는다.
- 두 계열은 표정/원형과 에너지/선 모양 등으로 구별하되 기분 하나의 표정을 에너지로 바꾸지 않는다.
- 주간의 매일 기록은 날짜별로 구분하고, 일정·분류·기록 종류를 같은 수준의 제목으로 중첩하지 않는다.
- 회고 작성란은 기존 펼침/내용 유무에 맞춰 보여 준다. 통계 카드·연속 기록 배지·자동 해석 문구를 추가하지 않는다.

### 찾기
- 검색창과 필터 버튼 → 날짜별 결과가 기본. 기존 별 표시 결과는 필터 안의 ‘다시 볼 기록’으로 접근시킨다.
- 분류는 한 필터 안에 일정별 / 기도·포커스·묵상 / 일정 무관을 둔다. 일정 무관을 별도 도구나 새 탭으로 만들지 않는다.
- Type, 일정/관련 문맥, 의미 태그, 다시 볼 기록은 서로 다른 역할로 유지하되 전부 기본 노출하지 않는다.
- 일정/관련 문맥은 선택한 분류에 유효할 때만 펼쳐 보여 준다. 기존 필터 기능을 삭제하지 않는다.
- 기본 결과는 날짜별 묶음 하나로 읽는다. 3분류를 날짜마다 다시 큰 제목으로 반복하지 않는다.
- 제목/첫 문장 → 미리보기 → 시간·문맥·필요한 태그. 별 표시는 기록 옆 보조 액션으로 유지한다.
- 필터를 쓴 경우에만 적용 개수/해제 경로를 표시한다. 빈 기본 칩 행은 두지 않는다.
- 월간 Mood 달력은 돌아보기 날짜 영역의 기존 월간 보기 경로에 재배치한다. 별도 Mood 탭을 추가하지 않는다.

## 6. Mood 표현 선택
| 안 | 특징 | 판단 |
| --- | --- | --- |
| OS 이모지 | 익숙하고 빠름. 플랫폼별 모양·색·크기 차이가 있음 | 빠른 탐색 시안에 적합 |
| 5단계 선형 얼굴 SVG | 선 굵기·크기·다크 대비를 통일, 값과의 매핑을 고정 | 제품 적용 우선안 |

- 표정은 기분 1~5의 기존 값을 표시한다. 사용자가 쓰지 않은 감정 이름·진단·평가를 붙이지 않는다.
- 얼굴은 다섯 단계, 색은 기존 Mood×Energy 25색을 사용한다. 에너지 값/막대와 기분 점수를 기본 화면에 중복 노출하지 않는다.
- 25색 Mood×Energy 매핑은 유지한다. 표정으로 기분을 읽고 색으로 기존 조합을 보조한다. 정확한 값은 접근성 이름/명시적 상세에서 확인 가능하게 한다.
- 얼굴 모양만 바꿔서는 충분하지 않다. 상단 위치·크기·텍스트·여백을 함께 조정한다.
- 24~32px 요약 얼굴, 16~20px 목록 얼굴, 약 2px 선을 시작값으로 검토한다. 실제 320px 렌더에서 확정한다.
- 미기록은 ‘기록 없음’으로 표시한다. 0점, 중립 표정, 희미한 웃는 얼굴로 대체하지 않는다.
- 기능성 SVG에는 현지화된 이름을 제공하고, 옆 텍스트가 같은 의미를 설명하면 장식 SVG로 처리해 중복 낭독을 막는다.
- 라이트/다크/흑백에서도 표정·선 종류와 숫자로 읽혀야 한다.

## 7. 공통 합격 기준
- 기본 읽기 상태에서 기록 위 컨트롤은 목적 탐색과 날짜/기간만 둔다. 날짜 오른쪽 표정과 별개로 감정 설명 영역을 만들지 않는다.
- 390×844, 기본 글자 크기, 짧은 예시 기록에서 Mood와 첫 기록의 시작이 첫 화면에 함께 보이는지 확인한다.
- 빈 날/긴 제목/많은 태그/기록 많은 날/기분만 기록/에너지만 기록/결측일을 각각 확인한다.
- 확대 글자에서는 첫 화면 노출보다 내용 손실 없는 세로 읽기를 우선한다.
- 확장 본문 15~16px, 줄간격 1.5~1.65를 출발점으로 기존 글자/줄간격 설정을 존중한다.
- 작은 아이콘과 터치 영역을 분리한다. 일반 액션 44×44px 목표, 달력은 간격/대체 경로 포함 예외를 검증한다.
- 본문/활성 도움말 4.5:1, 핵심 비텍스트 3:1 목표를 최종 합성 배경에서 측정한다.
- 320/390/1024 × 라이트/다크, 한영, 200% 확대, 키보드 포커스/상세 뒤로가기를 확인한다.
- 읽기/날짜 이동/필터/그래프 탐색이 저장 데이터를 바꾸지 않는지 비교한다.
- 검색·표시/해제·편집·자동저장·주간 회고·백업/복구 연결이 기존 의미를 유지해야 한다.
- 동작 동등성 및 데이터 보존 실패 시 새 화면을 출시하지 않는다.

## 8. 다음 산출물과 구현 경계
1. 이 기준을 바탕으로 같은 실제 예시 데이터를 넣은 현재/개편 하루·주간·찾기 화면 비교.
2. 320/390px에서 표정, 첫 기록 노출, 중복 라벨, 필터 펼침을 검토.
3. 화면 기준 확정 후 기존 렌더 함수/CSS를 한 경로씩 교체하고 이전 UI로 복구 가능하게 유지.
4. 기록 어댑터/저장 모델은 재사용. 새로운 감정 데이터·통계·화면·외부 라이브러리는 추가하지 않는다.
5. 별도 문서 브랜치에서 기획을 관리한다. 현재 단계에서 main 병합·앱 구현·배포는 하지 않는다.
