# On_HARU 수정 및 배포 검증

## 최종 후보 검증 — 2026-11-05 UTC

기존 On_HARU 구성과 로고, 메모 저장 키·스키마·마이그레이션을 유지했다. 아래 초기 감사의 배포 차단 문제를 수정했다.

- 완전히 동일한 Review CSS 규칙 4개의 앞쪽 사본만 제거(839바이트). 전체 CSS 일괄 정리는 하지 않았다.
- Capture 입력·일정·Review 탭·일정 편집창의 다크 대비를 수정했다. 라이트 일정 시각·비활성 탭도 4.5:1 이상으로 보완했다.

- 한국어에서도 실제 Escape·Tab·Enter 키로 처리하며, 최상단 팝업의 초점 이동·닫기를 바로잡았다.
- HTML·컨트롤러·설정·service worker 캐시 버전을 b7e4311050aa로 정렬했다.
- 기존 Workers 루트 경로와 /legacy/ 호환을 유지하며 릴리스별 원본 캐시와 응답 표식을 추가했다.

## 수정 내역

- Review의 완전히 동일한 루트 규칙 4개에서 앞쪽 사본만 제거했다. 같은 선택자·같은 선언·같은 적용 범위의 뒤쪽 사본을 유지했다. 미디어 쿼리, 선언 값, 규칙 우선순위, 컴포넌트 배치는 재작성하지 않았다.
- 대상: `#page-records .review-calendar-mode`, `.weekrow`, `.weekrow .d`, `.weekrow .h`.
- `scripts/audit-css.mjs --json`이 `--json`을 파일명으로 읽던 오류를 수정했다. 파일명 생략 및 명시 두 방식 모두 실행 가능하다.
- HTML 및 service worker의 캐시 릴리스 표식을 `a839c5511104`로 맞췄다. 이는 후보 브랜치의 캐시 일관성을 위한 변경이다.
- 6개 화면 구성의 브라우저 테스트, 원본/후보 CSS 비교, guided practice·기도·묵상·오프라인 테스트를 추가했다. 테스트와 결과물은 앱 배포 디렉터리 밖에 있다.

- 컨트롤러, 설정 런타임, manifest의 바이트가 기준 main과 동일하다. 데이터 키·스키마·마이그레이션·저장 함수는 변경하지 않았다.

## 확인한 문제

1. **다크 Capture 입력 글자 대비 부족.** 실제 계산 글자색은 `rgb(41,70,81)`, 투명 입력칸의 가장 가까운 불투명 배경은 `rgb(34,48,42)`다. 대비는 약 **1.37:1**로 4.5:1 기준에 못 미친다. 저장된 최근 메모의 대비 10.67:1과는 별개다. 원본과 후보 모두 동일하다. 독립 재검증의 320px 다크 일정 편집 화면에서는 흰 제목 입력칸 위에 매우 밝은 글자가 나타나는 문제도 보여 별도 대비 측정이 필요하다. 기존 `#page-capture #qc-v2 #qc-text`의 높은 specificity가 더 약한 다크 텍스트 규칙을 덮어쓰는 문제이며, 이번 중복 제거는 이 선택자를 수정하지 않았다.
2. **다크 Review 상단 탭 대비 부족.** 실제 렌더링 색과 앱 배경 `rgb(24,35,31)` 기준 Daily 활성 글자는 약 2.11:1, Weekly/Archive 글자는 약 3.59:1이다. 13px 텍스트이므로 4.5:1 기준에 못 미친다. 원본과 후보에 공통이다. 다크 Plan의 일정명·시각도 스크린샷에서 읽기 어려워 별도 대비 점검이 필요하다.
3. **기도 옵션 팝업의 겹침.** Focus → Prayer requests → 기도 추가 → 기도 옵션 → Edit title 경로에서 `focusLibraryModal`의 sheet가 `choiceModal` 버튼 위에 겹쳐 실제 클릭을 가로챈다. 강제 클릭으로 통과 처리하지 않았다. 320/390/1024px 양 테마에서 재현됐으며 이 영역의 앱 CSS·JS는 이번 중복 정리에서 변경하지 않았다.
4. **Settings의 일정 관리 진입 실패.** Settings → Daily routines의 Manage를 눌러도 일정 관리 화면으로 가지 않고 이전 화면으로 돌아오는 경로를 재현했다. Plan의 더보기 → 일정 편집 경로와 분리해 검증한다.
5. **한국어 모드 Escape 처리 실패.** 설정을 한국어로 적용하고 설정창을 연 뒤 Escape를 누르면 닫히지 않는 문제가 6개 구성에서 재현됐다. 키 이벤트 비교에 `KonaI18n.t("Escape")`를 사용하지만 한국어 카탈로그 값은 `Esc`다. 브라우저가 주는 키 값은 `Escape`이므로 일치하지 않는다. 같은 코드 패턴의 Tab/Enter도 별도 회귀 점검이 필요하다. 영어 반복 범위 팝업에는 일부 설명이 한글로 표시되는 혼재도 스크린샷에서 확인했다.
6. **과도한 전역 다크 규칙 유지.** `body .app * {color:inherit!important; ...}`와 다수의 강한 선택자 사이에 충돌 위험이 남아 있다. 원본에 있던 전체 규칙을 무리하게 제거하지 않았다.
7. **아주 작은 raster 차이.** 반복 캡처에서 동일한 computed style/geometry임에도 일부 버튼 가장자리·스크롤바에 소량의 픽셀 차이가 있다. 이미지 파일 불일치를 바로 레이아웃 회귀라고 단정하지 않고, 원본·후보·픽셀 차이를 함께 확인했다. 정확한 최종 비교 숫자는 아래 실행 결과에 기록한다.

### 원본 로그와 재검증의 관계

원본 기능 행렬 로그는 105/126, 확장 흐름 로그는 24/36 통과다. 여기에는 테스트가 내부 i18n 키 `Edit event`/`Edit recurring event`를 화면에 실제 표시되는 `Edit`/`Edit repeats`로 잘못 찾던 일정 편집·반복 편집 12건이 포함된다. 해당 선택자는 정정했고, 같은 앱 코드에서 독립 테스트로 **12/12 통과**를 확인했다. 이 12건을 제품 결함으로 집계하지 않는다. 원본 로그를 덮어쓰거나 전체 CI가 통과했다고 표시하지 않았다.
